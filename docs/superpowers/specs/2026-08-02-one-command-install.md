# One-command Install Entrypoint (B1.5) — Design

**Status:** Draft for review.
**Date:** 2026-08-02
**Scope:** Sub-project B1.5 of the "easy setup" program. Wraps the existing `scripts/install/bootstrap-swarm.sh` (B1) in a friendly single entrypoint so first install is `git clone` + one `sh`. Domain setup (B2) and in-UI version update (B3) are separate specs.

## Goal

Make production first-install this, with no need to hand-set env vars:

```bash
git clone <repo> /opt/evcp && cd /opt/evcp
sudo ./install.sh
```

`install.sh` interactively collects the few real inputs (image repository, version, optional GHCR credentials), shows a summary, confirms, then runs the full B1 bootstrap (swarm init → generate Docker secrets → deploy → OpenBao init/unseal) and prints the access URL. A non-interactive mode (all inputs via env/flags) is kept for automation.

Distribution: **clone + run** (the repo is private single-enterprise; no public `curl | sh`). A public curl one-liner is explicitly out of scope.

## Background

`scripts/install/bootstrap-swarm.sh` already performs the entire install but requires the operator to export `EVCP_IMAGE_REPOSITORY`, `EVCP_VERSION`, optional `EVCP_GHCR_USER`/`EVCP_GHCR_TOKEN`, etc. This spec adds a human-friendly front door; it does not change the bootstrap mechanics.

## Components

### `install.sh` (new, repo root)

A thin POSIX `sh` wrapper:

1. **Preflight:** Docker present + `>= 25`; running as root (or re-exec with `sudo`); confirm this is the repo root (`scripts/install/bootstrap-swarm.sh` exists).
2. **Collect inputs** (prompt only when unset; every value overridable by env/flag so a fully-specified invocation runs non-interactively):
   - `EVCP_IMAGE_REPOSITORY` — default derived from the `origin` remote host → `ghcr.io/<org>` (e.g. `ghcr.io/0xlabsteam`); operator confirms/edits.
   - `EVCP_VERSION` — default the latest local `v*` git tag (`git describe --tags --abbrev=0` / `git tag` sort); operator confirms/edits.
   - GHCR credentials — ask "are the images private? (y/N)"; if yes, prompt `EVCP_GHCR_USER` + `EVCP_GHCR_TOKEN` (token read with no echo). Skipped if the images are public or already `docker login`ed.
3. **Summary + confirm:** print the resolved image repo, version, advertise address (auto-detected IP), and access URL; ask to proceed (skip with `--yes`/`EVCP_INSTALL_ASSUME_YES=1`).
4. **Run bootstrap:** `exec` `scripts/install/bootstrap-swarm.sh` with the collected values exported. Bootstrap owns the actual work + the final "open http://…" + OpenBao secure-store warning.

Flags: `--yes` (non-interactive), `--version <v>`, `--image-repository <repo>`, `--dry-run` (forwarded to bootstrap). No secret is ever prompted, printed, or written to disk by `install.sh` (secrets are auto-generated by bootstrap).

### Docs

Update `docs/operations/swarm-deploy.md`: lead with `git clone … && sudo ./install.sh`; keep the manual/`bootstrap-swarm.sh` details as reference.

## Data flow

`install.sh` (prompts) → exports non-secret inputs → `exec bootstrap-swarm.sh` (unchanged B1 flow) → stack up, URL printed.

## Error handling

- Docker missing / version `< 25` / not root / not in repo root → exit early with a clear message.
- Empty required input after prompt (image repo/version) → re-prompt or exit non-zero with guidance.
- GHCR login failure → surfaced by bootstrap (`docker login`), install aborts before deploy.

## Testing

- **Unit (headless):** drive `install.sh` with `--dry-run --yes` and all inputs via env; assert it (a) resolves the image-repo default from a stubbed remote, (b) resolves the version default from a stubbed tag, (c) forwards `--dry-run` to bootstrap and creates nothing, (d) never prompts and never emits a secret when `--yes` + inputs are set. Use a PATH-injected `docker`/`git` stub like `tests/unit/bootstrap-swarm.test.mjs`.
- **`sh -n`** on `install.sh`.
- **Live:** on the local single-node swarm, `sudo ./install.sh --yes` with `EVCP_IMAGE_REPOSITORY=evcp-local EVCP_VERSION=test` brings the stack up (reuse the verified B1 e2e path), then teardown.

## Acceptance criteria

- `git clone … && sudo ./install.sh` brings up the whole stack with at most a few confirmable prompts and zero secret input.
- Fully non-interactive when inputs are supplied (`--yes` + env) — usable from automation.
- `install.sh` only orchestrates; all bootstrap mechanics stay in `bootstrap-swarm.sh` (no duplication).
- `install.sh` never prompts for, prints, or persists a secret.

## Out of scope

- Public `curl | sh` one-liner and any public installer hosting.
- Domain/TLS setup (B2) and in-UI version update (B3).
- Downloading a release bundle instead of a clone.
